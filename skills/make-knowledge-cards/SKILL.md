# 知识卡片生成

把一篇文章压成 5-8 张可复习的卡片。成败只有一个标准：读者只看卡片，能否拿回原文里真正重要的东西。

## 输入

- 直接粘贴的文章，可能包在代码块、引用块或"以下是全文："之后。
- 本地 `.md` / `.txt` 文件路径。先读文件再处理；路径不存在或读不出内容时直接说明，不要按文件名猜内容。
- 用户给多篇时逐篇处理，每篇一组卡片并标注出处，不要混成一组。
- 用户附带偏好（"多讲实操""只保留概念""准备考试用"）时按偏好调整选点，卡片字段、数量规则、不编造规则不变。

## 流程

1. 通读全文，判断文本类型（科普、教程、评论、报告、笔记）和作者主张。
2. 列出候选知识点：一段能独立成立的完整论述，就是一个候选。
3. 按重要性筛到 5-8 个。
4. 合并重复：同一知识点在全文多处出现时只留一张，取信息最完整的那处表述。同一动作在不同日期重复出现、同一结论和它的直接机制，也算重复。
5. 逐张成卡，顺序跟原文逻辑走：概念 → 机制 → 方法 → 易错点。
6. 过一遍自检清单，不合格就改。

## 选点判据

优先保留：

- 核心主张与结论，以及支撑它的关键理由
- 机制、原理、因果链（为什么会这样）
- 关键概念与定义（不懂就接不上后文的）
- 方法、步骤、操作要点
- 关键数据、对比、边界条件
- 常见误解与易错点

直接舍弃：

- 背景铺垫、行业套话、过渡句、修辞与情绪
- 与主张无关的举例堆砌
- 同一意思的反复强调
- 纯时效性细节（某次会议、某人近况），除非它本身就是结论

筛完仍超过 8 个，按上面的顺序取前 8，其余丢掉。不要把两个知识点塞进一张"大杂烩"卡。

## 按文本类型选点

同一套规则在不同文本上侧重点不同：

- **教程/步骤类**（操作说明）：按"阶段"和"判断条件"成卡，不要按日期或原文段落切。同一动作出现在多个日子时合并成一张。判定"是否做好"的标志单独成卡。
- **数据/报告类**：核心知识先给结论（"增长仍在两位数""缺口集中在晚高峰"），具体数字放解释或例子栏，不要把数字罗列当核心知识。报告自带的局限（未提供某数据、口径不明）保留一张，因为读者需要知道结论的边界。
- **观点/评论类**：取主张、支撑理由、对主要反驳的回应，以及最后的判断标准。情绪表达和重复口号一律不进卡片。
- **清单/要点类**：每条一个卡片，不要合并成"几条建议"；条数不足 5 时按信息量说明，不补内容。
- **短文本**（一两句话）：能成几张就是几张，宁可 2-3 张，也不要靠常识扩写。

## 卡片字段

每张卡四项齐全：

- **标题**：≤16 字，写知识点名字（"边际成本为什么递减"），不要写成句子开头。
- **核心知识**：一句话，≤50 字，说清这张卡要记住什么。不铺垫、不设问。数据型文本里，这里写结论，不写数字清单。
- **简明解释**：2-4 句，讲清是什么、为什么、怎么用，让没读过原文的人也能懂。只展开原文已有的内容，不引入原文没有的因果、机制、关系判断；原文没给理由时写"原文未给出理由"，不要替它补。
- **例子或自测问题**：从下面三项选一项。
  - 原文有例子、案例：压成一句，写成"原文举例：……"。
  - 原文有可引用的数据或对比：写成"原文数据：……"，一条就够。
  - 都没有：出一道能一句话回答的自测题，附"答案：……"，答案必须能在原文里找到。

一张卡只讲一个知识点。出现"而且""另外""顺带还能"就是拆卡信号；拆完超过 8 张，就砍次要的，不要拓宽范围。

需要标注原文缺什么时，在卡片最后单独一行写"原文未说明：……"，不要塞进"例子/自测"栏。

## 不编造

- 只用原文出现过的信息。数字、人名、机构、因果关系、"研究表明"都要能在原文找到。
- 允许通俗化改写、补连接词；不允许新增事实、数字、对比结论或"常识补充"。
- 解释里不出现原文没有的名词和判断。原文只写"目前没有统一答案"，就不要补"因为个体体重、恢复能力不同"——那是你的常识，不是原文。
- 原文没说清或自相矛盾时照实写（"原文未给出具体数值"），不要替它补全。

## 语言

- 卡片语言跟随用户这轮提问的语言。用户没指定、文章是英文时用中文，专有名词保留英文原词，首次出现处给中文。
- 用陈述句。不写"本文将……""让我们……"，也不写"非常重要""值得注意"这类空评价。

## 数量

- 正常文章 5-8 张。
- 信息确实不足（短消息、清单、单一结论）时给 2-4 张，并把开头的"共 N 张"写成"原文信息量有限，共 N 张"。
- 不为凑数拆空洞卡片，也不为整齐删掉重要内容。用户明确要固定数量时按用户要求，并在开头说明取舍。

## 输出

默认直接在对话里输出 Markdown，不写文件；用户要求保存时写到指定路径，默认 `<主题>-知识卡片.md`。模板：

```markdown
# <主题> · 知识卡片

共 N 张

## 1. <标题>
- **核心知识**：……
- **简明解释**：……
- **例子/自测**：……

## 2. <标题>
……
```

- 首行标题写文章主题，不照抄原文的长标题。
- 卡片之间不加串场句，结尾不加总结段，不加"希望有帮助"。
- 不加字数、耗时、模型之类的说明。

## 示例

输入片段："睡眠不足会降低瘦素水平、升高胃饥饿素水平，因此人更容易感到饥饿。一项针对 12 名志愿者的实验显示，连续两晚只睡 4 小时后，受试者次日平均多摄入 300 千卡。"

输出（其余卡片同格式）：

```markdown
# 睡眠与食欲 · 知识卡片

共 N 张

## 1. 缺觉为什么会变饿
- **核心知识**：缺觉改变两种食欲激素，让饥饿感被放大。
- **简明解释**：瘦素负责传递饱腹信号，胃饥饿素负责传递饥饿信号。缺觉让前者下降、后者上升，所以人更容易饿。
- **例子/自测**：原文举例：12 名志愿者连续两晚只睡 4 小时，次日平均多摄入 300 千卡。
```

## 自检

出稿前逐条过：

1. 每张卡是不是只有一个知识点？
2. 相邻两张是否在讲同一机制、同一动作或同一结论的不同侧面？删掉一张后另一张是否仍完整？是则合并。
3. 核心知识是否一句话，解释是否真的解释了它？数据卡的核心知识有没有只是复述数字？
4. 解释里有没有原文没有的因果、机制、关系判断？原文没给理由时是否如实标注？
5. 例子或自测题是否来自原文、能否回答？
6. 有没有原文查不到的说法？重点查数字、因果、"研究表明"。
7. 数量是否在 5-8 之间，或已按信息量说明？删掉任意一张会丢重要信息吗？
8. 只看卡片能否独立看懂，不依赖原文？

## 不做

网页抓取（用户给 URL 时请其贴正文）、PDF/图片/扫描件解析、Anki 或 Quizlet 导出、图形界面。遇到这类输入，直接说明当前不支持，并请用户改贴正文或提供 `.md`/`.txt`。
